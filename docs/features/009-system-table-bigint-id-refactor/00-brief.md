# 00 Brief

## 问题重述

- 多张系统表仍使用字符串主键，与项目新的数据库规范不一致，也增加了模型与接口类型维护成本。

## 用户与场景

- 项目维护者需要统一系统表主键设计，降低后续扩展和数据库治理成本。

## 价值判断

- 统一改为自增 `bigint` 后，数据库、Go 模型、OpenAPI、前端类型能够保持一致，减少额外转换和隐式约定。

## 已知事实 / 推断 / 假设

- 目标表旧数据无需保留，可通过重建表完成升级。
- `sys_files` 历史磁盘文件本轮不清理，只处理数据库记录。

## 主要风险

- `sys_files` 与 `sys_options` 已对外暴露 `id` 字段，本次需要同步更新契约和前端类型。
- schema version 提升后，旧库必须先执行升级 SQL 才能启动。

## 最小落地路径

- 修改 bootstrap SQL、补升级 SQL、更新 store 与接口类型、执行生成与验证、补 feature 文档。

## 结论

- `继续`
