# 10 PRD

## 功能目标

- 将 6 张系统表的 `id` 统一改为自增 `bigint`，并让对外暴露的文件/配置 `id` 类型同步调整。

## 用户角色

- 项目维护者
- 后台管理员

## 典型用户流程

- 维护者执行升级 SQL 后启动服务。
- 管理员继续上传/查询/删除文件，新增/编辑系统配置，接口返回数值型 `id`。

## 范围内 / 范围外

- 范围内：schema 重构、升级 SQL、Go 模型、OpenAPI、前端类型、相关测试与文档。
- 范围外：旧数据迁移、历史上传文件清理、按 `id` 更新系统配置的接口设计。

## 状态与边界条件

- 旧数据直接丢弃后重建表。
- `option_key` 仍是系统配置的业务主键，写接口继续按 key 工作。

## 异常与失败路径

- 旧库未执行升级 SQL 时，schema 校验阻止服务启动。
- 文件接口收到非法 `id` 时，返回请求参数错误。

## 验收标准

- 6 张目标表主键均为自增整数。
- `sys_options.option_key` 显式使用唯一约束 `uk_o`。
- `Option.id`、`File.id` 以及 `/files/{id}` 的路径参数均为 `int64`。
- 相关业务流程和测试通过。
