# 10 PRD

## 功能目标

- 新增一个泛型、最小封装的缓存组件，支持 key 前缀、可选全量加载器和可选自动刷新。
- 使用该组件重构 `option` 缓存实现，但不改变 `option` 对外调用方式。

## 用户角色

- 后端开发者
- 维护系统配置读取与更新逻辑的服务实现者

## 典型用户流程

- 开发者创建 `pkg/cache.Cache[string, T]`，按需配置前缀、刷新周期和全量 loader。
- 业务层调用 `Get` / `Set` / `Del` / `GetAll` 使用缓存；需要时调用 `Refresh` 或 `Run`。
- `option` 服务在读缓存 miss 时主动刷新一次，再返回最新配置值。

## 范围内 / 范围外

- 范围内：内存快照、全量刷新、前缀命名空间、可选后台刷新、`option` 重构、相关测试和文档。
- 范围外：TTL 逐项过期、单 key loader、持久化写回、深拷贝 value、OpenAPI 或配置项变更。

## 状态与边界条件

- 未配置 loader 时，`Refresh` / `Run` 返回明确错误。
- `Run` 首次调用先同步刷新一次；已启动后再次调用为幂等 no-op。
- `RefreshInterval <= 0` 时只完成首次同步刷新，不启动后台循环。

## 异常与失败路径

- loader 返回错误时，`Run` 初始化失败并返回错误；后台循环中的失败不应导致 goroutine 崩溃。
- `option` 在读取 miss 且刷新后仍未命中时，继续返回 `errOptionNotFound`。

## 验收标准

- `pkg/cache` 提供约定接口并通过针对前缀、刷新、并发边界的单测。
- `option` 继续支持字符串读取、JSON 读取、写库后立即刷新和后台自动刷新。
- 仓库最低检查命令全部通过。
