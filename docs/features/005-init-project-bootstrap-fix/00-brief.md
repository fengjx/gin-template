# 00 Brief

## 问题重述

- README 中模板初始化脚本 raw 地址仍指向错误仓库，用户按文档执行会拿不到正确脚本。
- `scripts/init-project.sh` 初始化后直接删除 `.git`，导致用户无法继续跟踪模板仓库修复。
- `admin` 首次 `npm install` 后存在 2 个已知安全告警，影响模板初始化体验。

## 用户与场景

- 使用 `gin-template` 快速初始化新项目的开发者。
- 需要在项目初始化后保留与模板仓库的同步能力，同时希望开箱安装依赖时不出现安全告警。

## 价值判断

- 修复 README 和初始化脚本可直接提升首屏使用体验，减少新用户卡在第一步。
- 保留模板历史和 `template` 远程可降低后续同步上游修复的成本。
- 在模板仓库中修复 lockfile 能让下游项目首次安装即处于安全版本。

## 已知事实 / 推断 / 假设

- 模板仓库地址为 `https://github.com/fengjx/gin-template`。
- 用户已确认初始化后采用“保留历史，只把远程改为 template”的策略。
- `npm audit` 已确认当前告警来自 `brace-expansion@2.0.2` 与多处 `picomatch` 版本过低。

## 主要风险

- 修改初始化脚本后若远程重命名顺序不当，可能导致克隆后 git 远程状态异常。
- 若仅刷新 lockfile 不能稳定消除漏洞，可能需要追加最小依赖约束。
- README 模板区块起止标记不完整，若修复不当可能导致初始化后仍残留模板说明。

## 最小落地路径

- 修复 README 中脚本地址、模板仓库地址与模板说明块边界。
- 调整初始化脚本保留 `.git`、重命名远程为 `template` 并规范为 HTTPS。
- 刷新 `admin/package-lock.json` 到无审计告警的安全依赖版本。

## 结论

- `继续`
